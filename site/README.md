# The microsite

One long page about worxpad, published at <https://worxbend.github.io/worxpad/> by
`.github/workflows/pages.yml` on every push to main. It is plain HTML and CSS: no JavaScript, no npm,
no bundler, no framework, no third-party scripts. The only outside request is the Archivo font from
Google Fonts. Adapted from the macropad microsite, without its scroll scenes.

| File | What it is |
| --- | --- |
| `index.html` | The page: every section, every caption, every alt text. |
| `style.css` | Colours, type and layouts. |
| `README.md` | This file. It is not published. |

## How the page is built

`make site` runs `tools/build_site.py`. It builds into `_site.staging/` and moves the result to `_site/`
only when every check passes (`make site-serve` uses `_site.staging-serve/`, so the two can run at once).
It:

- copies the `.html`, `.css`, `.js` and `.svg` files of this folder;
- copies every file the page names as `images/<group>/<file>` from `docs/images/<group>/<file>`, at build
  time. A new render therefore needs no change to the site unless its pixel size changes;
- writes resized WebP copies of the PNG renders when Pillow is installed (CI installs it). Without
  Pillow the `<source type="image/webp">` lines are removed and the PNGs are used. The copies are
  cached in `.build/site-webp/` until the PNG changes.

The pictures in `docs/images/` are generated by `make renders`, `make pcb-place` and `make cad`. Never
edit them by hand, and never copy them into this folder: name them from the page instead.

```bash
make site                                   # build once; exit 1 when a check fails
make site SITE_PYTHON=cad/.venv/bin/python  # the same with Pillow, so the WebP copies are written
make site-serve                             # build, serve http://127.0.0.1:8000/, rebuild on every change
make site-serve SITE_PORT=8080
```

`make site-serve` watches this folder, `docs/images/` and the Markdown files the page links into. A
rebuild that fails prints its problems and keeps serving the last good build. After editing
`build_site.py` itself, stop the server and start it again.

## Adding a section

1. Add a `<section id="..." class="chapter">` inside `<main>` with an `h2`, and keep the heading levels
   in order.
2. Name pictures as `images/renders/x.png`, `images/cad/x.png` or `images/pcb/x.png`.
3. Give every `img` a `width` and a `height` equal to the picture's own size, an `alt` that says what
   the picture shows, and `loading="lazy"`. For a PNG render, add a `<source type="image/webp">` line
   with a half-width and a full-width copy, as the other pictures do. An SVG's size is its root width
   and height in CSS pixels (KiCad writes millimetres: 1 mm is 96 / 25.4 px).
4. Link a guide as `https://github.com/worxbend/worxpad/blob/main/<path>`; the build checks the path.
5. Add a header link if the section matters.

## The checks

`make site` fails when:

- the page names a file that is not in `docs/images/`, or a WebP copy wider than its PNG;
- a picture (PNG, GIF, JPEG, WebP or SVG, any letter case, any depth) in `docs/images/renders`,
  `docs/images/cad` or `docs/images/pcb` is not shown. Shown means an `<img src>`, a WebP `<source>` in
  the same `<picture>` as that `img`, or a `<source>` of a `<video>`; a plain link does not count. Show
  it, or add it to `SKIP` in `build_site.py` with a one-line reason;
- a `SKIP` entry names a missing file, a file that is shown anyway, or has no one-line reason;
- a local link, picture or `#anchor` does not resolve in `_site/`, or an id is used twice;
- a link to `github.com/worxbend/worxpad/blob/main/...` or `/tree/main/...` names a path that is not
  in the checkout, or its `#anchor` has no heading in that Markdown file (`README.md` for a link to
  the repository itself). Headings are turned into anchors as `tools/check_docs.py` does;
- an image lacks `width`, `height` or `alt`, its `width` and `height` are not the picture's own size
  (a re-render with a new size must update the page), an empty alt is not inside
  `aria-hidden="true"`, or an image after the first is not lazy;
- the page has more or fewer than one `h1`, or a heading skips a level;
- the page loads a script from another site, or a stylesheet from anywhere but Google Fonts;
- a WebP `<source>` is not on a line of its own (without Pillow those lines are removed);
- the build's own self-check of its patterns and readers fails.

## Rules

- Every claim must be true for this design and taken from the repository: `README.md`, `board.toml`,
  `docs/` and the subsystem READMEs. Plain technical English, British spelling, no marketing.
- Nothing has been built, printed, milled or switched on. The header pill, the hero, the captions and
  the status section say so. Keep them.
- The status table is copied from the status table in `README.md`. When that table changes, change
  this page in the same commit.
- The commercial macropad used as a reference is never named as the product, and none of its name,
  logo, artwork or files appears here.
- The page must read completely with JavaScript off. It has no JavaScript today; if a widget is ever
  added, everything it shows must also be in the HTML.
