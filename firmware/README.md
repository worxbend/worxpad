# worxpad firmware

ZMK for the worxpad board: one nRF52840 in a u-blox BMD-340 module. The firmware builds; it has never run on a
worxpad, because no board exists yet. Everything below that talks about behaviour describes what the code is
written to do, not what was seen.

Status of the last build: see [Build](#build).

## What it does

- 16 keys (4 x 4 matrix with diodes, col2row), two knobs with push, two round buttons. The pushes and buttons
  sit on a fifth matrix column (`board.toml` `[matrix]`).
- Four layers: Edit, Nav, Media, System. The default keymap is described in [docs/keymap.md](../docs/keymap.md).
- USB HID and Bluetooth LE HID with four host profiles. Output follows ZMK's rules: USB when plugged into a host,
  else the selected Bluetooth profile; the System layer switches it by hand.
- ZMK Studio over USB (serial) and Bluetooth. Unlock with left button plus row 1, column 4.
- Status screen on the 240 x 240 panel, our own layout: knob functions at the top (turn and push), the 16 key
  functions of the active layer in a grid, and a status bar with the layer name, USB or the Bluetooth profile
  (grey while not connected) and the battery percentage with a charge mark. The number turns red under 10 %.
  The labels are read from the live keymap, so Studio edits show after the next layer change.
- Battery level from the MAX17048 gauge (ZMK driver), also reported to hosts over the Bluetooth Battery Service.
- Charging state from the BQ24072 /CHG and /PGOOD lines. The lines raise no event, so the screen polls them
  once a second while USB power is present, and after unplugging until the mark is off.
- Backlight on PWM, 40 % by default (`CONFIG_WORXPAD_BACKLIGHT_PERCENT`).
- Power: after 30 s without input ZMK's blank-on-idle stops the LVGL tick and sends DISPOFF, and
  `src/display_power.c` switches the backlight off and sends the panel to sleep-in (SLPIN). Input reverses it:
  SLPOUT, DISPON, the tick restarts and the backlight returns. After 15 minutes on battery ZMK enters deep sleep (System OFF); a key press wakes it. The QSPI flash is
  under runtime power management, so it sits in deep power-down when not read.
- Radio at +8 dBm, the module maximum, for the aluminium body.

Not in this firmware:

- **No clock.** The board has no time source. A clock needs the host widget channel (Raw HID, mcu-radio record
  5.4), which is not written yet.
- **No host widget channel and no icon store.** The W25Q128JV is declared only so that it sleeps.
- **Gauge alert pin unused.** The ZMK MAX17048 driver polls; P0.26 is wired but not read.
- **Gauge sleep not enabled.** MODE.EnSleep stays 0, so with the switch off the gauge auto-hibernates (3 uA
  typ) instead of sleeping (0.5 uA). Sleep would stop the gauge while the cell charges with the switch off,
  and the data sheet says to wake it before charging. The power record's off-current figure assumes sleep.
- No low-battery soft-off (the power record calls it optional).

## Layout

```
zephyr/module.yml                          makes the repository a Zephyr module (board root firmware/zmk)
firmware/build.sh                          build in the pinned image -> firmware/dist/worxpad.uf2
firmware/zmk/config/west.yml               ZMK and Zephyr pinned by commit
firmware/zmk/Kconfig, CMakeLists.txt       module options and sources
firmware/zmk/src/status_screen.c           LVGL status screen
firmware/zmk/src/labels.c, labels.h        short labels for keymap bindings
firmware/zmk/src/display_power.c           backlight level, panel sleep on idle
firmware/zmk/boards/worxbend/worxpad/      board definition (hardware model v2) and the default keymap
firmware/dist/worxpad.uf2                  GENERATED by firmware/build.sh
```

Pins live in `board.toml` `[pinmap]`. The board files repeat them by hand;
`tools/check_pins.py` (part of `make test`) runs `tools/check_pins_firmware.py` and fails when they disagree.

## Build

```bash
make firmware          # or: bash firmware/build.sh
```

`firmware/build.sh` tags `zmkfirmware/zmk-build-arm:stable` from the digest in `tools/images.lock`, makes a west
workspace under firmware/.build/ws (ignored by git), fetches the modules once with network (about 3 GB), then
builds with `--network none`:

```
west build -s zmk/app -b worxpad//zmk -S studio-rpc-usb-uart -- -DZMK_EXTRA_MODULES=/w -DCONFIG_ZMK_STUDIO=y
```

The full log is firmware/.build/worxpad.log.

Pinned revisions: ZMK `4dd95d7840eb3d5a3f59bb29fbf1ab054715ef85` and Zephyr
`10ba6d0cb38bc3d258775d27982f707599320085` (both in firmware/zmk/config/west.yml; the Zephyr commit is what
ZMK's branch `v4.1.0+zmk-fixes` resolved to on 2026-11-13). The Zephyr modules come from that Zephyr
manifest, LVGL and the Studio messages by commit from ZMK's; Zephyr SDK 0.16.9 in the image.

Last build, 2026-11-13: passed. FLASH 391,252 B of 811,008 B (48.24 %), RAM 122,242 B of 262,144 B (46.63 %).
`firmware/build.sh` also checks that the UF2 carries family 0xADA52840 and starts at 0x26000, as the Adafruit
bootloader needs. Two warnings, none from worxpad code: the deprecated Kconfig symbol `KSCAN`, set by ZMK, and
an implicit declaration of `pm_device_runtime_enable` in ZMK's `kscan_gpio_matrix.c`, which misses an include
when `CONFIG_PM_DEVICE_RUNTIME` is on. The call links to the real function.

## Checks

| Check | Command | What it covers |
| --- | --- | --- |
| Pin map | `make pin-check` | every devicetree and pin-control pin against `[pinmap]`; unused nets accounted for; no spare pin used; pulls; sleep states; matrix, transform and physical layout against `[keys]`, `[encoders]`, `[buttons]`; encoder steps; display clock, size and PWM period; bindings per layer |
| Build | `make firmware` | the board definition, keymap and module code compile and link for the nRF52840; the UF2 family and start address suit the Adafruit bootloader |

There are no host unit tests for the screen code.

## Untested

All of it on hardware. In particular:

- The ST7789V register values are Zephyr's example set, not the DisplayModule init sequence. MADCTL 0x00 and
  zero offsets assume the flex-toward-the-front mounting; the picture may be upside down or shifted by 80 lines
  (display record 6.5). RGB565 byte order is not checked.
- SPI at 16 MHz is 6 % over the ST7789V write-cycle figure (mcu-radio 7.5).
- Panel sleep: the order of ZMK's blank-on-idle work and the worxpad wake work on the display queue is not
  fixed. The wake work sends DISPON after SLPOUT so that both orders should give a lit, awake panel; not seen.
- Idle current with the hooks (target 100 uA or less, mcu-radio 7.7) is not measured.
- `&uicr gpio-as-nreset` makes the application write PSELRESET on first boot if the bootloader left it empty.
- Bluetooth range in the aluminium body at +8 dBm.
- The Adafruit bootloader 0.11.0 has no worxpad board header yet ([docs/flashing.md](../docs/flashing.md)).
- USB IDs are the pid.codes test pair 1209:0001. Not for distribution.
